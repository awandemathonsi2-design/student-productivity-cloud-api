# Student Productivity Cloud API

A REST API for managing student tasks, built with Java, Javalin and PostgreSQL. Runs locally with Docker and is deployed to AWS using EC2 and RDS.

## Overview

This is a Cloud Computing proof project. It's a small, complete backend: create, view, update and delete tasks, backed by a real PostgreSQL database, running both locally and in the cloud.

## Problem

Students juggle assignments, revision and deadlines. This API is the backend for a simple task manager, so a student (or a future frontend) can track tasks and their completion status.

## Features

- Create, list (all or one), update and delete tasks
- Input validation with clear JSON error messages
- Persistent storage in PostgreSQL
- Configuration via environment variables (no secrets in the code)
- Automated tests against a real database and a real running API
- Deployed on AWS: EC2 running the app, RDS running the database

## Architecture

**Local**

Client (Postman) sends a request to the Javalin API on port 7070.
The API calls TaskController, which validates the request and calls TaskRepository.
TaskRepository runs SQL against PostgreSQL, running in Docker on port 5432.

**AWS**

A client on the internet sends a request to EC2 on port 7070.
EC2 runs the same Java application as a background service.
EC2 connects privately to RDS PostgreSQL on port 5432.
RDS is not reachable from the internet, only from EC2's security group.

## API Endpoints

| Method | Path | Description | Success |
|---|---|---|---|
| POST | `/tasks` | Create a task | 201 |
| GET | `/tasks` | List all tasks | 200 |
| GET | `/tasks/{id}` | Get one task | 200 |
| PUT | `/tasks/{id}` | Update a task | 200 |
| DELETE | `/tasks/{id}` | Delete a task | 204 |

Errors are JSON, e.g. `{"ERROR": "Title is required"}`, with status 400 (bad input) or 404 (not found).

Example:
```bash
curl -X POST http://localhost:7070/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Study AWS","description":"Finish the Cloud Computing project"}'
```

## Local Setup

Requires Java 21, Maven, Docker.

```powershell
docker compose up -d postgres
mvn clean package -DskipTests
java -jar target\student-productivity-cloud-api-1.0-SNAPSHOT.jar
```

The API runs at http://localhost:7070.

## Running Tests

Tests run against a real PostgreSQL database, so start it first:

```powershell
docker compose up -d postgres
mvn test
```

- `TaskRepositoryTest` — tests every repository method directly against PostgreSQL
- `TaskApiTest` — starts the real API on a random port and tests it over real HTTP, including error cases

Tests create and delete their own data, so your existing tasks are never affected.

## AWS Architecture

- **EC2** (`t3.micro`): runs the Java/Javalin API as a systemd service (`student-api.service`), so it restarts automatically if the server reboots.
- **RDS** (`db.t3.micro`, PostgreSQL, 20 GiB): managed database, not publicly accessible.
- **Security groups:**
    - `StudentProductivity-api-sg`: allows SSH (from my IP) and port 7070 (from anywhere).
    - `StudentProductivity-db-sg`: allows PostgreSQL (5432) only from `StudentProductivity-api-sg`. The database is never exposed to the public internet.

## AWS Deployment (summary)

1. Create an RDS PostgreSQL instance (`db.t3.micro`, 20 GiB, not publicly accessible).
2. Create two security groups: one for EC2 (SSH + 7070), one for RDS (5432 from the EC2 group only).
3. Launch an EC2 instance (`t3.micro`, Amazon Linux 2023) with the EC2 security group attached.
4. Install Java 21 on the instance: `sudo dnf install -y java-21-amazon-corretto-headless`.
5. Build the fat JAR locally: `mvn clean package -DskipTests`.
6. Copy it to EC2: `scp -i key.pem target\*.jar ec2-user@<ip>:~`.
7. Set environment variables in `/etc/student-api.env` and run the app as a systemd service, so it survives reboots and SSH disconnects.
8. Test from a browser or Postman at `http://<EC2-public-ip>:7070/tasks`.

## Lessons Learned

- That Javalin needs Jackson configured before it can turn Java objects into JSON.
- Prepared statements protect against SQL injection.
- Optional makes a missing task part of a method's return type, instead of relying on null checks.
- Environment variables let the same code run locally and in the cloud, only the values change.
- A server's security group needs correct outbound rules, not just inbound ones, or it cannot reach the internet.
- Running the app as a systemd service is what lets it survive a closed SSH session and restart if the server reboots.
